# ZhanaGasyr · IELTS Mock Tests

Закрытая платформа IELTS Academic: администратор создаёт аккаунты и назначает экзамены, ученик проходит четыре секции, преподаватель оценивает Writing/Speaking, администратор публикует результат.

**Статус:** рабочая первая версия для разработки и демонстрации. 39 серверных тестов проходят. Перед учебным запуском нужны настоящие материалы, проверка production-инфраструктуры и приёмка на реальных устройствах. Демонстрационные баллы и история не являются оценками реальных учеников.

## Быстрый запуск

Требования: Python 3.12+, `ffmpeg` / `ffprobe`. SQLite включена в Python. В production предусмотрен PostgreSQL через `DATABASE_URL`.

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
bash scripts/start-dev.sh
```

Приложение слушает порт **8000**. `seed_demo` создаёт администратора, преподавателя, ученика и сокращённый экзамен. Случайные пароли записываются в **`var/demo-credentials.json`**, который исключён из Git. Команда повторяется безопасно и не меняет существующие пароли. Демонстрационная озвучка генерируется `ffmpeg` с фильтром `flite`.

Без демоданных создайте первого администратора:

```bash
.venv/bin/python manage.py bootstrap_admin --email admin@your-domain.kz
```

Пароль запрашивается скрытым вводом. Публичной регистрации и стандартных паролей нет. Нельзя использовать демобазу для реальных учеников.

## Реализовано

- Четыре роли с серверными проверками, закрытая активация, одноразовые ссылки, смена/восстановление пароля, блокировка, отзыв сессий, ограничение попыток входа.
- Пользователи, группы, конструктор четырёх секций и вопросов, приватные материалы, неизменяемые опубликованные версии и клонирование.
- Назначения ученикам/группам, сроки и лимиты, последовательные секции, серверный таймер, фоновое завершение просроченных секций.
- Автосохранение с контролем версии ответа, локальные текстовые черновики, обнаружение конфликтов вкладок.
- Listening с однократным запуском; Reading; два Writing с подсчётом слов; запись/загрузка трёх частей Speaking и локальное восстановление неотправленных записей.
- Настраиваемые таблицы raw → band, ручные критерии, двойной вес Task 2, IELTS-округление Overall, черновики проверки и отдельная публикация.
- История, графики опубликованных результатов, очередь проверки, CSV с защитой от формул, аудит, резервное копирование SQLite и проверяемое восстановление.
- Адаптивный интерфейс в тёмно-зелёной/светлой палитре, поддержка клавиатуры, мобильная навигация.

## Проверка

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py test core
node --check static/core/app.js
node --check static/core/exam.js
```

Тесты проверяют авторизацию, CSRF, изоляцию учеников/преподавателей, активацию, отзыв сессий, лимиты, серверные сроки, конфликты сохранения, неизменяемость версий, файлы и полный цикл оценки/публикации.

## Структура

| Модуль | Назначение |
|---|---|
| `config/` | Конфигурация, маршруты, WSGI |
| `core/models.py`, `core/migrations/` | Данные, ограничения целостности и миграции |
| `core/auth_views.py`, `core/middleware.py` | Закрытый доступ и сессии |
| `core/exams.py` | Контракт экзамена и расчёт оценок |
| `core/services.py` | Транзакции попыток, таймеры, проверка и публикация |
| `core/views.py`, `core/forms.py` | Управление и кабинеты |
| `core/exam_views.py`, `core/media.py` | Экзаменационные API и приватные файлы |
| `templates/core/`, `static/core/` | Интерфейс и браузерное сохранение/запись |
| `core/management/commands/` | Начальная настройка, демонстрация, таймеры, backup/restore |
| `docs/` | ТЗ, архитектура, руководство и эксплуатация |

Конфигурация — переменные окружения из `.env.example`. Django сам `.env` не читает: перед запуском экспортируйте переменные либо передайте их через менеджер процессов/Docker. Файлы `var/`, `.env` и виртуальное окружение не входят в репозиторий.

## Границы первой версии

Это модульный Django-монолит, а не предложенная в ТЗ связка Next.js/NestJS. В пустом репозитории нечего было переиспользовать; решение сокращает число отдельно развёртываемых компонентов и использует стандартные средства безопасности Django. Архитектурное решение описано в `docs/ARCHITECTURE.md`.

- Отправка email требует SMTP. Без SMTP администратор выдаёт ссылку через доверенный канал.
- Приватные файлы хранятся на локальном диске. S3, горизонтальное масштабирование, live Speaking и ИИ не подключены.
- Составные таблицы/карты представлены текстом, изображением и отдельными короткими ответами; drag-and-drop редактора нет.
- Строгий прокторинг/DRM не реализован. Ограничение прослушивания не предотвращает запись аудио на устройстве.
- Подготовка Part 2 — вспомогательный минутный таймер; сервер строго ограничивает всю секцию Speaking, а не отдельные реплики.
- CSV-импорт пользователей и расширенные аналитические фильтры оставлены для следующего этапа.
- При полной потере сети после окончания времени поздние ответы не принимаются. Сохранённую локальную копию можно передать администратору для разбора технической ситуации.
- Полный производственный банк вопросов, нагрузка, мобильная запись, политика хранения/удаления данных и согласия должны пройти отдельную приёмку.
