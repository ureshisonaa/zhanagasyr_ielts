# Архитектура и этапы

## Аудит

Репозиторий `ureshisonaa/zhanagasyr_ielts` не содержал файлов, коммитов или существующей системы авторизации. Исходный стек и хостинг отсутствовали. ТЗ 1.1 рассматривается как требования к продукту; предложенный TypeScript-стек в документе не являлся обязательным.

## Решение

Django 5.2 LTS, Python 3.12, серверные HTML-шаблоны и небольшие изолированные JS-модули. Это один модульный backend без разделённых cookie-доменов и дублирования правил между frontend/backend. PostgreSQL предусмотрен конфигурацией; локальные разработка и тесты используют SQLite. Все версии Python-пакетов зафиксированы в `requirements.txt`.

Данные экзамена объединены в валидируемый JSON-контракт `TestVersion.content`. Это позволяет хранить полную неизменяемую версию, включая вопросы, варианты, ключи, тайминги и шкалы. Данные учеников, назначения, попытки, секции, оценки, файлы и аудит имеют отдельные реляционные модели и ограничения. Шкалы и ключи не попадают в ученический HTML/API.

## Последовательность реализации

1. Основа, конфигурация, модели и миграции.
2. Роли, вход, активация, блокировки и управление группами.
3. Редактор версий, вопросы, приватные файлы, публикация и назначения.
4. Транзакционная машина состояний попытки и UI четырёх секций.
5. Автооценка, ручная проверка, публикация и аналитика.
6. Проверки доступа и полного сценария; browser smoke; backup/restore; документация.

Каждый блок использует общие модели и сервисы; расчёты и права не дублируются в клиентском коде. ИИ, оплаты и публичная регистрация не добавлены.

## Инварианты

- Назначение закрепляет конкретную версию и проверяющего. Изменения группы не переназначают ранее выданные работы.
- Опубликованная версия неизменяема через ORM `save` и все прикладные маршруты. Новая версия создаётся клонированием. Прямые SQL-записи и `QuerySet.update` — привилегированные средства эксплуатации, не публичный интерфейс.
- У одного назначения может быть одна активная попытка. Номер попытки уникален в назначении.
- Начало новой секции — время отправки предыдущей либо её исходный deadline, если время истекло. Перезагрузка/закрытие браузера не даёт паузу.
- `due_at` ограничивает всю попытку. `expire_attempts --loop` обрабатывает сроки без браузера; запросы также проверяют сроки.
- Каждое сохранение содержит revision. Устаревший revision получает 409; текущий ответ не перезаписывается.
- Файл имеет единственного родителя: версия или сданная/активная секция. Сервер проверяет содержимое и доступ при каждом чтении, включая Range-запросы.
- Teacher работает только с назначенными попытками. Student видит оценки исключительно в `published`.
- Исправление опубликованной оценки требует специального разрешения и возвращает результат в непубличное состояние до повторной публикации.

## Эксплуатационные ограничения

SQLite подходит для локальной демонстрации, не подтверждает целевую конкурентную нагрузку. Production следует запускать с PostgreSQL и отдельно тестировать гонки/нагрузку. Хранилище локальное приватное; служебные файлы нельзя раздавать nginx по `/media/`. Нет очереди email: SMTP вызывается синхронно. Не существует фиктивного ИИ-оценивания или автоматического утверждения Writing/Speaking.

Расширение: вынести файловое хранилище за интерфейс Django Storage; добавить отдельный модуль предложений ИИ и очередь, не изменяя опубликованные `Review` и `Attempt.overall`.
